# รายงานสรุปฉบับเต็ม: โครงการ OPX

วันที่: 26 ต.ค. 2026 · สถานะ: **เสร็จสิ้นการทดสอบ ผลคือ NO-GO (ไม่ผ่านทั้ง 15 การตั้งค่า)**

---

## 1. สรุปสำหรับผู้บริหาร

- **เป้าหมาย:** สร้างระบบ ML ทำนายทิศทางราคา FX ที่ M1/M5/M15 สำหรับสัญญา Fixed-Time (Binary Options) แล้วตรวจสอบว่ามี edge จริงเหนือจุดคุ้มทุนหรือไม่
- **ผลลัพธ์:** ระบบทำงานครบและผ่านการทดสอบ 57 รายการ แต่เมื่อรันบนข้อมูลจริง 5 คู่เงิน × 3 กรอบเวลา (ข้อมูล M1 ราว 11.8 ปี ประมาณ 4.4 ล้านแท่งต่อคู่) **ไม่มีการตั้งค่าใดผ่านเกณฑ์ครบ 8 ข้อ**
- **สิ่งสำคัญที่เกิดขึ้นระหว่างทาง:** การรันรอบแรกรายงาน **GO** สองรายการ (EURUSD k=15, GBPUSD k=15) แต่การตรวจสอบ (audit) พบว่าเป็น **ผลลวงจากช่วง Rollover ของนิวยอร์ก** ไม่ใช่ edge จริง หลังกรองช่วงนั้นออกแล้วรันใหม่ทั้งหมด ผลทุกรายการเป็น NO-GO
- **ข้อสรุป:** ไม่ควรนำเงินจริงไปเทรดด้วยผลจากระบบนี้ การที่ระบบจับ false positive ได้เองและปฏิเสธการเทรดคือผลลัพธ์ที่ถูกต้องตามเจตนาของการออกแบบ

## 2. งานวิจัยที่ใช้เป็นฐาน

มี 3 แหล่ง (อยู่ใน `docs/research/`) สรุปไว้ที่ [summary.md](summary.md)

| แหล่ง | เนื้อหา | น้ำหนักความน่าเชื่อถือ |
|---|---|---|
| R1 (ไฟล์ .md) | การประเมินเชิงหลักฐาน มีอ้างอิง ระบุว่า accuracy นอกตัวอย่างที่ทำได้จริงราว 50–52% | สูง |
| R2 (.docx ภาษาอังกฤษ) | พิมพ์เขียวเทคนิคยาว มีสูตรและโค้ด แต่อ้างผลลัพธ์ดี (win rate +1–7%, Sharpe 1.4) โดยไม่มีหลักฐานตรวจสอบได้ | ใช้เป็นวิธีการ ไม่เชื่อตัวเลขผลลัพธ์ |
| R3 (.docx ภาษาไทย) | สรุป 4 แหล่ง: repo วิจัย quant, ผู้ขาย API สำหรับ Binary Options, เปรียบเทียบแพลตฟอร์ม, บทความ custom loss | ส่วนใหญ่ไม่เกี่ยวข้อง |

**จุดที่ทุกแหล่งเห็นตรงกัน:** จุดคุ้มทุน `p* = 1/(1+r)` (54.05% ที่ payout 85%), ใช้ GBDT ไม่ใช่ deep learning, loss แบบถ่วงน้ำหนักตาม payout, calibrate ความน่าจะเป็น, validate แบบ purged walk-forward, **ห้าม Martingale**, **ห้ามใช้ข้อมูล OTC**

**จุดที่ขัดแย้งและการตัดสินใจ:** ใช้เกณฑ์ `breakeven + buffer` แทน 0.60 คงที่, ตัด OTC ออก, ใช้ขนาดเดิมพันคงที่ 1%, ใช้ Platt calibration, และถือว่าตัวเลขผลลัพธ์ของ R2 เป็นเพียงสมมติฐาน

**R3 และผู้ขาย API:** ไม่ใช้ API ของ CB Traders BD เพราะขายโค้ดที่หลบระบบกัน bot (Cloudflare Turnstile) สนับสนุน Martingale และอ้าง win rate 90%+ โดยไม่มีหลักฐาน

## 3. สถาปัตยกรรมและการพัฒนา

รายละเอียด: [architecture.md](architecture.md) · แผน 13 งาน: [แผนการพัฒนา](superpowers/plans/2026-10-26-opx-pipeline.md)

```
M1 bars → labels (entry=open[t+1], expiry=close[t+k], เสมอ=แพ้)
        → features (เฉพาะข้อมูล ≤ t)
        → purged walk-forward (6 folds) + LightGBM(loss ถ่วงน้ำหนัก payout) + Platt calibration
        → เลือกเทรด: p_cal > breakeven + buffer (ไม่ซ้อนทับกัน)
        → Gate 8 ข้อ → รายงาน GO / NO-GO
```

**Gate 8 ข้อ (ต้องผ่านทั้งหมด):**
1. ขอบล่าง Wilson 95% ของ win rate > จุดคุ้มทุน
2. Deflated Sharpe Ratio ≥ 0.95 (หักค่าการลองหลายแบบ)
3. Probability of Backtest Overfitting ≤ 0.2
4. Permutation test p < 0.01
5. Payout stress: ยังเหนือจุดคุ้มทุนเมื่อ payout ลดลง 5 จุด
6. Lag stress: ยังผ่านเมื่อ slippage เพิ่ม 2 เท่า
7. Calibration error < 2%
8. เสถียรรายไตรมาส: อย่างน้อย 75% ของไตรมาสเป็นบวก

**สถานะโค้ด:** 12 โมดูลใน `src/opx/` (ใช้ pandas, numpy, lightgbm, scikit-learn, scipy, httpx เท่านั้น), ทดสอบ 57 รายการผ่านทั้งหมด รวมถึงการทดสอบว่า pipeline **ต้องเจอสัญญาณที่ฝังไว้** และ **ต้องปฏิเสธสัญญาณรบกวนล้วน** ระบบ live (`live.py`) ทำได้เพียงตัดสินใจและส่งแจ้งเตือน Telegram **ไม่มีการเทรดอัตโนมัติ**

**การแก้ไขระหว่างทาง:** เพิ่ม import ที่ขาดและทดสอบ PBO หลาย buffer, เพิ่มตัวกรอง `skip_illiquid` (ดูหัวข้อ 5), เร่งความเร็ว permutation test ด้วย hypergeometric (ทดสอบเทียบกับค่าที่แน่นอนแล้ว)

EURUSD k=15 และ GBPUSD k=15 ผ่านครบ 8 ข้อ แต่การตรวจสอบ ([audit-eurusd-k15.md](audit-eurusd-k15.md)) พบว่า:

| เทรดทุกชั่วโมงยกเว้น NY 17:00 | n=12,771, win **53.75%** ต่ำกว่าจุดคุ้มทุน 54.05% |

## 6. ข้อจำกัดและสิ่งที่ยังไม่ได้ตรวจสอบ

1. **ข้อมูลไม่ใช่ราคาตัดสินของโบรกเกอร์** เป็น bid ของ Dukascopy ผลผ่านบนข้อมูลนี้จึงเป็นเพียง "จำเป็น" ไม่ใช่ "เพียงพอ"
2. **ไม่ได้วัดความหน่วงระดับวินาที** ข้อมูลละเอียดสุดคือ 1 นาที ผล "เข้าช้า" จึงวัดได้เป็นก้าว 60 วินาที ค่าประมาณระหว่างจุดเป็นการประมาณ ไม่ใช่การวัด
3. **k=1 และ k=5 อื่น ๆ ยังไม่ได้ตรวจสอบเชิงลึก** (ชั่วโมง, เข้าช้า, placebo) ยกเว้น GBPUSD k=5 เหตุผลคือทุกรายการห่างจากเกณฑ์มากกว่า
4. **การเลือก buffer จากข้อมูลทดสอบเดียวกัน** DSR และ PBO ชดเชยเรื่องนี้ ซึ่งเป็นเหตุผลที่สองเกณฑ์นี้ไม่ผ่าน
5. **ข้อสันนิษฐานเรื่อง Rollover** ยังไม่ได้ตรวจ spread โดยตรง
6. **ต้องทำด้วยมือก่อนใช้เงินจริง (ไม่มีในโค้ด):** ถูกกฎหมายในเขตของคุณหรือไม่, ทดสอบ forward demo 500–1,000 เทรดที่ไม่ซ้อนทับ, วัดความต่างระหว่างฟีดข้อมูลกับราคาตัดสินของโบรกเกอร์

## 8. บทเรียนเชิงกระบวนการ

1. **ผ่านเกณฑ์ ≠ มี edge** ต้อง audit ทุกครั้งที่ได้ GO ครั้งนี้ตรวจแล้วเป็น artifact
2. **Planted-signal และ pure-noise test** ช่วยยืนยันว่า pipeline ไม่ได้พังเอง ก่อนเชื่อผลจริง
3. **การเลือกค่าจากข้อมูลทดสอบ** (เช่น buffer) สร้างผลลวง ต้องดูความไวของผลต่อพารามิเตอร์ ไม่ใช่ดูแค่จุดที่ดีที่สุด
4. **เขียนข้อสรุปหลังมีผลเท่านั้น** ร่างรายงานแรกประกาศ NO-GO ก่อนรันเสร็จและขัดกับผลที่บันทึกไว้ ต้องเขียนใหม่ทั้งฉบับ
5. **ผลที่ดูดีเกินไปต้องสงสัย** edge ที่กระจุกอยู่ในชั่วโมงเดียวและโตขึ้นตามเวลาคือสัญญาณเตือน
